---
title: Connect devices
description: Pair a trusted device with an existing PiChamber server.
---

On the server, create a one-time pairing link:

```sh
pichamber connect-url --qr
```

If no server is running on the selected port, `connect-url` starts one before
creating the link. Use `--port <port>` to select a running instance,
`--server https://host.example.com` when the public URL differs from the local
bind address, or `--relay` to include the private relay as a fallback.

On a Docker server, open the browser UI first and use **Add a device** there.
You can also run `docker compose exec pichamber bun packages/web/bin/cli.js connect-url --qr`
from the compose directory.

**Add a device** asks where you will use the device:

- **Tailscale (recommended)** is selected when this computer is on a tailnet.
  The QR code points at the server's Tailscale address, so the device connects
  at home and away as long as both run Tailscale. Tick **Also try your home
  Wi-Fi when Tailscale is off** to add the home network address as a second
  address the device tries.
- **Home network only** points at the server's Wi-Fi or LAN address and works
  only on that network. It is selected when Tailscale is not running.
- **This computer only** is for apps on the same machine.

Tailscale and the home network require the server to accept network
connections (`--lan`, or local network access in the desktop app's settings).
Without that, both options are greyed out.

Open or scan the link from the device you want to connect. Pairing grants that device access to the server's workspace, so use it only for devices you control. Revoke access from the server when a device is no longer trusted.

Remote PiChamber clients operate on the server's filesystem and use the server's Pi configuration and credentials.
