# Session Sidebar Documentation

## Architecture & Layout

- `SessionSidebar.tsx` orchestrates sidebar components and lifecycle; core state and rendering logic lives in focused hooks and components.
- Layout (web/desktop): the session list starts at the top of the sidebar. Chrome and session cards share a `0.75rem` (`px-3`) gutter; the session scroller is full-width so its overlay scrollbar sits on the sidebar edge. `SidebarNav` uses that same gutter so New session lines up with the icon toolbar, and only grows left to clear OS window chrome. It shares the header height and vertical centering of the content-area session title. On dedicated mobile (phone drawer), New session is a full-width floating button docked at the sidebar bottom, above the session list over a sidebar-toned fade, not a `SidebarNav` row or a FAB on the drawer scrim. While worktree tasks exist, the Background tasks control floats immediately above it and opens the shared task list. The scroller keeps `pb-32` on mobileVariant so the last rows clear both controls. The button stack hides while the bulk-selection bar owns the bottom edge. The tablet sidebar keeps the `SidebarNav` control instead.
- **Chats**: sessions created with "Don't work in a folder" have no project owner. They live under the Chats node at the top of the tree with a neutral theme-aware row shade.
- **Workspace tree** (`SidebarWorkspaceTree`, #95): one list replaces the old projects bar and session zones. Chats (home sessions) come first, then registered projects in their manual order; a project with linked worktrees expands to its `main` checkout and one row per worktree, a project with one checkout lists its sessions directly. Rows are 24 px with guide lines (hosted mobile raises them to its 36 px touch floor). Clicking a project or worktree selects and expands it and opens no session; the selection (`stores/useSidebarSpaceStore.ts`, `selectedNodeKey`) only marks where New session lands and never filters the list. Expansion is per device in `oc.sidebar.tree.expanded.v1`, written only by `useWorkspaceTreeExpansion`. Collapsed nodes show the model's rollup: a spinner while a child runs, else the unread dot, then the session count.
- **Activity indicator**: While a session is running (`busy`/`retry`), the row shows a spinner and elapsed turn time. When a background session finishes a turn, the relative timestamp is replaced by a foreground unread dot until that session is opened. Aggregate indicators for collapsed folders and projects show a spinner while any child is running, or the unread dot when a finished turn is still unseen.
- Session rows have a single layout and bold titles while unread; they carry no branch label, because the worktree row above them names the branch. Fork families use the same theme-aware tinted row backgrounds on desktop, tablet, and mobile. The active session uses the selection fill only; the title color does not change. Session rows do not show files-changed or diff counts. Hovering a row swaps the relative timestamp (or live status) for the archive action in the same slot so the title does not shift. Session rows do not open hover or long-press tooltips; the visible title and meta are the only session summary.
- **Session folders** nest inside their worktree or flat project as tree nodes, after that container's sessions. A folder belongs to one folder scope (the container's directory); the row menu offers Rename, New subfolder and Delete folder, and worktree and flat project rows offer New folder.
- **Drag and drop** (`treeDnd.tsx`, rules in `treeDrop.ts`, effects in `applyTreeDrop.ts`): one `DndContext` for the whole tree, mouse after 8 px, touch after a 200 ms hold from a drag handle (a press on the row itself opens the context menu). A project row drops on another project row to reorder; a session drops on a folder or its container, a folder on another folder or its container. Drops stay inside one folder scope, because leaving it would change the session's directory, and a folder never drops into its own subtree. `resolveTreeDrop` decides both the drop and the hover highlight.
- **Keyboard** (`treeKeyboard.ts`, `hooks/useTreeKeyboard.ts`): the tree uses `role="tree"` and roving focus, one `treeitem` is the tab stop. Up/Down/Home/End move focus, Right expands or enters, Left collapses or climbs to the parent, Enter opens a session or selects and toggles a container, `n` starts a new session on Chats, a project or a worktree. Keys act only when they start on the treeitem, so inputs and buttons in a row keep their own keys.
- **Quick search**: the header search narrows the tree itself (debounced 120 ms) to matching projects, worktrees, folders and session titles, highlights the hit in container labels and session titles, and counts `matchCount`. It opens the model's `searchExpanded` overlay on top of nothing: `useWorkspaceTreeExpansion` keeps toggles made during a query in memory for that query only, so Esc (clear, then close) restores the stored expansion unchanged. Selecting a session clears the search.
- **Visibility**: `ProjectVisibilityMenu` hides whole roots (Chats or a project) per runtime, persisted in settings `hiddenProjectIds`. Hidden projects keep loading; only the tree omits them, and the search still reaches them. With everything hidden the empty state offers Show hidden projects.
- Archived sessions are not shown in the web/desktop sidebar; the Archive dialog (`ArchiveView`, `useUIStore.isArchivePageOpen`) replaces the old toggle. Restore (unarchive) is available per session (row context menu, Archive dialog row) and in bulk (selection bar) and writes `time.archived = 0`.
- Directory loading is catalog-driven: `PiSessionCatalogFeeder` fills every known project/worktree directory (deduped by sorted signature) through the catalog's at-most-2-in-flight scheduler. The catalog keeps each successful directory snapshot independently, so activating or opening a session in one project never removes sessions belonging to another; a failed directory refresh preserves that directory's prior rows and flips only its list status. The session list stays mounted while the sidebar is closed so opening it can slide with `transform` instead of remounting the tree. Close collapses layout width immediately, in the same 200ms easing as the header title spacers, so the session title does not slide right (header reserving toggle space) and then left (sidebar width dropping). Hidden-sidebar subscriptions still gate on `isVisible`.

## Design decisions (#95)

The tree replaced the spaces bar and session zones in seven pull requests (#100 to #121 and the quick create pull request). The reasons that still constrain changes:

- **One owner per fact.** Where a session belongs: `createSessionOwnershipIndex` only, which returns home and ownerless sessions instead of dropping them. Tree shape, order, the five-session cut and rollups: `workspaceTree.ts` only; renderers never sort or filter. Running and waiting: the live status index, never persisted history. Selection: `selectedNodeKey`, which never filters. Expansion: `oc.sidebar.tree.expanded.v1`, one writer, per device. Project order: `useProjectsStore.manualProjectOrder`. Visibility: `useProjectVisibilityStore`, synced like other UI settings. Git status of rows: one scheduler with `useGitStore` as cache. Pull request state: requested once per worktree. Target of a new session: the selected node, or the row whose `+` was clicked.
- **Order** (D8): Chats fixed on top, projects in manual order; in a project the primary checkout, then worktrees by last activity; sessions running, waiting, pinned, then by recency, at most five plus an "N more" row. Forks nest collapsed under their parent with a fork count; merged worktrees sit dimmed in an "N merged" group and are never deleted automatically.
- **Other folders** (D11) is computed only once worktree discovery is complete, otherwise sessions of a worktree would flash there.
- **Hidden projects keep loading** (D16), so search still finds them; hiding never stops `PiSessionCatalogFeeder`.
- **Git pills** (D4): changes are staged plus unstaged plus untracked; `↑`/`↓` only when not 0; a failed status shows `?` and never reads as clean. Visible rows only, at most 2 light status calls at once, 60 s cadence, refresh on expand, window focus and the end of a session turn.
- **Auto fetch** (D17): off by default; one fetch per repository root, for the projects shown, one at a time, paused while the window is hidden. A repository is due when its last attempt, failed or not, is one interval old, so nothing refetches early and failures cannot loop. Git runs with prompts disabled and a 60 s timeout on the server, so a fetch fails instead of waiting for credentials.
- **`+` only on workspace rows** (Chats, worktrees, flat projects), in the fixed count slot. A new session is a draft until its first prompt, so `+` needs no server call. Touch has no hover; the long press menu carries New session.
- **Drops stay inside one folder scope.** Moving a session across worktrees would change its working directory, which needs a real move operation first. Touch drags from a handle because a press on the row opens its menu.
- **No virtualization** until a measurement on real data asks for it: `buildWorkspaceTree` took 0.21 ms per rebuild at 16 worktrees and 200 sessions; search only removes rows.
- **Hard cutover**: the tree used new storage keys and started from defaults; old keys are neither read nor migrated.

## File summaries

### Components

- `SidebarHeader.tsx`: Top header UI for add-project, the visibility menu, quick search, selection mode, and archive access. Projects retain their manual order; there is no sidebar display/sort menu. On dedicated mobile the toolbar occupies `var(--oc-header-height, 56px)` with `px-2` / `size-9` round icon buttons (`size-4` icons) so the chrome matches the chat header height without oversized sidebar type. Add folder / Add project still go through `sessionEvents.requestDirectoryDialog()`; dedicated mobile mounts `SessionDialogs` so the explorer overlay actually opens.
- `SidebarWorkspaceTree.tsx`: The sidebar list. Renders the rows `visibleRows` produces: container rows (Chats, project, worktree, folder, "N more") with guide lines, count slot and context menu (right-click or the 500 ms long press from `hooks/useLongPressMenu.ts`), and session rows through `SessionNodeItem` in the `'tree'` render context. Rows only render; ordering and placement come from `workspaceTree.ts`. It hosts the drag and drop provider and the roving keyboard focus.
- `TreeContainerRow.tsx`: Container row (Chats, project, worktree, folder, "N more") with guide lines, git slot (`WorktreeGitPills` on worktree and flat project rows, the `N dirty` rollup on a collapsed project), count slot, rollup indicator, context menu and inline folder rename (`TreeFolderRename.tsx`). Rows that take a new session show a `+` over the count slot on hover or keyboard focus of the `treeitem` (the `group/row`); it is a sibling button of the row button, skipped on touch-only pointers and dedicated mobile, where the row menu's New session item is the route. Worktree rows expose `Close worktree`; the confirmation blocks close while that worktree's rollup reports a running session. `treeNodeMenu.tsx` builds each row's menu, `treeNodeLabel.ts` its accessible label.
- `SidebarNav.tsx`: Text-style New session control (no row chrome or hover background; label brightens on hover) plus hide-sessions control above the tree; hidden on the dedicated mobile phone sidebar, which uses a floating New session button docked at the sidebar bottom instead. On desktop the top strip is a window-drag region with a no-drag carve under the persistent PiChamber menu overlay so Electron cannot steal those clicks while the sidebar is open.
- `SidebarFooter.tsx`: Static footer with icon-only settings, shortcuts, and about actions. Hidden on mobile; those actions live in the mobile sidebar header.
- `SessionNodeItem.tsx`: Renders one session row/tree node with a single-line layout, indicators, menu actions, and nested children. Pending-question counts stay per-session while expanded and roll up hidden descendants from their owning directory stores while collapsed. Rows do not wrap the title in a tooltip or paint an inner press fill; the row selection/hover chrome is the only highlight. The row menu (`SessionNodeContextMenu.tsx`) holds the one orchestrator switch (#136) for sessions without a parent: it reads `orchestration.orchestrators` from `/api/pi/settings` when the menu opens, stays hidden until it knows the state, and sets or removes the mark through `setPiChamberDefaults`.
- `ConfirmDialogs.tsx`: Shared confirm dialog wrappers for session delete, folder delete, and worktree close flows. Worktree close checks Git status before enabling the destructive action, requires explicit acknowledgement for dirty files, preserves the local branch, and refuses active worktrees.
- `sessionOwnership.ts`: Resolves session directories once into shared project/worktree ownership and folder-scope indexes. Worktree ownership comes from Git discovery, not filesystem containment beneath the project path. Home sessions come back as `globalSessions` and sessions no project owns as `unownedSessions`, so callers can account for every session.
- `workspaceTree.ts`: Pure model of the workspace tree (#95): Chats, projects with worktrees, folders and forks, Other folders; order, the five-session cut, rollups and default expansion. Every active session lands in exactly one node. Rendered by `SidebarWorkspaceTree`. `folderScopesByProject` and `sessionsByProject` derive bulk-selection scopes and project session lists from the same tree. Optional `hidden` (project ids plus `chats`, from `useProjectVisibilityStore`) drops those roots; a non-empty `query` instead narrows the tree to matching projects, worktrees, folders and session titles with their ancestors, includes hits in hidden projects (root marked `hiddenMatch`), dissolves the "N more" cut, and returns a transient `searchExpanded` overlay plus `matchCount`. `parents` and `placement` always describe the unfiltered tree; the stored expansion is never touched.
- `quickCreate.ts`: Which rows take a one-click new session (`canQuickCreate`: Chats, worktrees, flat projects) and `createSessionInWorkspace`, the single path from the header New session button, key `n`, the row menu item and the hover `+`. It closes full-page surfaces, shows chat, opens a draft with `openNewSessionDraft({ selectedProjectId, directoryOverride })` (Chats: `__home__`, the store resolves the home directory or `~`), leaves a compact layout, then focuses the composer unless the caller withholds it (dedicated mobile, where it would raise the keyboard). A session stays a draft until its first prompt (`createSession` in `sync/session-ui-draft-helpers.ts`), so no server call is involved.
- `treeDrop.ts`, `applyTreeDrop.ts`, `treeDnd.tsx`: drop rules, store effects and the dnd-kit wiring described above.
- `treeKeyboard.ts`: Pure key-to-action mapping for the tree.
- `worktreeStatusScheduler.ts`: Framework-free scheduler for the light git status of visible worktree rows: at most 2 fetches at once, one in flight per path, 60 s cadence per visible path counted from the end of the last attempt (failures retry at the same cadence), on-demand `refresh`/`refreshVisible`, `setActive(false)` while hidden, `dispose`. Records `ready` or `failed` per path; a failure keeps the last known status apart and is never read as clean. Clock and timers are injected.
- `WorktreeGitPills.tsx`: Renders a worktree's pills (icons, status colors, tooltips with the fetch time) and is the only sidebar place that calls `useEnsureGitHubPrStatus`: once per rendered worktree, not once per session row. Session rows no longer show a pull request badge.
- `worktreePills.ts`: Pure mapping from a scheduler record plus PR summary to the pill model of D4 (`dirty`, `clean`, `ahead`, `behind`, `no-upstream`, `attention`, `unknown`, `pull-request`) and the project `N dirty` rollup. Renderers own icons, colors and strings.

### Hooks

- `hooks/useProjectSessionSelection.ts`: Fed from the tree's project session lists. Resolves active/current project-session selection logic and session-directory context. While a new-session draft is open it does not steal the view onto an existing session; the draft target follows the sidebar's active project instead. Switching a project/folder still loads that folder's remembered or first session in the background, but dedicated mobile keeps the sessions drawer open so the user can pick a different session. Opening Settings from the mobile sidebar closes the drawer.
- `hooks/useSessionActions.ts`: Centralizes session row actions (select/open, rename, share/unshare, archive/delete, confirmations). Explicit session picks still close the mobile sessions drawer; project-folder auto-selects pass `keepPanelOpen`.
- `ProjectVisibilityMenu.tsx`: Header checklist of the tree roots (Chats and every project) backed by `useProjectVisibilityStore`; Show all and Hide all. A hidden root still shows, marked, when the quick search matches inside it.
- `hooks/useWorkspaceTreeModel.ts`: The one place that turns store data (projects, discovered worktrees, ownership, folders, pins, live activity, unseen) into `buildWorkspaceTree` input, keeping the previous tree while discovery is incomplete.
- `hooks/useWorkspaceTreeExpansion.ts`: Single writer of tree expansion; applies `defaultExpanded` when nothing is stored and opens the active session's ancestors once when it changes.
- `hooks/useLongPressMenu.ts`: Shared 500 ms long press that opens a row's context menu on touch.
- `hooks/useTreeKeyboard.ts`: Roving tab stop and key handling for tree rows.
- `autoFetchScheduler.ts`: Framework-free timer for Auto fetch (slice 6 of #95). API: `createAutoFetchScheduler({ fetchRepository, onFetched, now?, timers? })` returns `configure({ enabled, intervalMs })`, `setRepositories(repositories)`, `setActive(active)`, `getSnapshot()`, `subscribe(listener)`, `dispose()`. The unit is a repository (its project root), never a worktree, and only the visible projects' repositories are given to it. One fetch at a time. A repository is due when it was never attempted or its last attempt (success or failure) is at least the interval old, so enabling, a changed interval, a newly visible repository and `setActive(true)` fetch only what is due and never early; failures retry at the normal cadence. After a success `onFetched` gets the repository's visible worktree paths for a light status refresh. The snapshot holds per root `lastFetchedAt`, `lastError` and `lastAttemptAt`; a failure keeps the last good time and blocks no other repository. Clock and timers are injected.
- `hooks/useAutoFetchScheduler.ts`: React binding of `autoFetchScheduler.ts`, mounted by `SidebarWorkspaceTree`. Fetches through `useRuntimeAPIs().git.gitFetch(root)` (the server runs it non-interactively with a 60 s timeout), reads the `gitAutoFetchEnabled` and `gitAutoFetchIntervalMinutes` settings (Settings > Git, off and 15 minutes by default, allowed 5/15/30/60 via `lib/autoFetchSettings.ts`), pauses while the page is hidden, and rebuilds the scheduler on a runtime or git API change. Returns the per repository state, which `WorktreeGitPills` shows in the ahead and behind tooltips (`formatAutoFetchNote`); empty while the setting is off.
- `hooks/useWorktreeStatusScheduler.ts`: React binding of `worktreeStatusScheduler.ts` (slice 5 of #95), mounted by `SidebarWorkspaceTree`. Fetches light git status through `useGitStore.fetchStatus` (the cache), refreshes on window focus, pauses while the page is hidden, and rebuilds the scheduler on a runtime or git API change. `refresh(path)` is for expand and the end of a session turn.
- `hooks/useAuthoritativeSessionCleanup.ts`: Establishes the first complete active+archived list as a non-destructive baseline, then cleans persisted state only for sessions omitted by a later authoritative snapshot.

### Types and utilities

- `types.ts`: Shared sidebar types (`SessionNode`).
- `sessionNodeItemUtils.ts`: Memoization and extraction utilities for session node rows.
- `utils.ts`: Deduplication, search matching, path normalization, and shared row class names.
- `highlightedText.tsx`: Search highlight markup for session and group labels.
- `sidebarRowChrome.tsx`: Session-shaped row buttons.
